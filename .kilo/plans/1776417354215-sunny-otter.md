# Plan: Release LUCID v2 Pipeline & Datasets

## Objective
Package and release the LUCID v2 SISR dataset filtering pipeline as a polished, user-friendly open-source tool, then publish two datasets (Elite_complex_05 and Probe_CC0_06) with full documentation.

---

## Part A: Clean Pipeline Release

### A1. Define Scope & Architecture
**Simplified 3-Step Pipeline for Public Consumption:**

1. **AUDIT** (optional) – Check/corrupt fix + color profile standardization
2. **FILTER** (core) – Tiling + 6 signal thresholds + IC9600 complexity scoring
3. **DEDUPE** (optional) – ResNet18-based texture deduplication

**Exclude from public release** (too specialized):
- Ghost scoring/reintegration (05, 06)
- Sequential finalizer (07) 
- Multi-dataset lineage mapping (04)

### A3. Simplified User Workflow
```bash
# Install (one-liner)
pip install lucid-sisr  # or from GitHub: pip install git+https://...

# Basic usage – simplest possible
lucid filter --input /path/to/images --output /path/dataset

# With all options
lucid filter \
  --input /path/to/images \
  --output /path/dataset \
  --tile-size 256 \
  --complexity-threshold 0.6 \
  --dedupe --dedupe-threshold 0.96

# Audit existing tiles
lucid audit --input /path/to/tiles --fix

# Just dedupe existing dataset
lucid dedupe --input /path/to/tiles
```

### A4. Core Improvements for Public Release

**Script `filter.py` (merged, simplified)**:
- Single-command operation (no multiprocessing queue management exposed)
- Clear progress bars: "Stage 1/3: Tiling (2.3k images)...", "Stage 2/3: Quality filtering...", "Stage 3/3: Complexity scoring..."
- Automatic device detection + graceful CPU fallback
- Resume capability: skip already-processed images
- Single CSV output: `manifest.csv` with columns: `tile_name, source_image, complexity_score, entropy, lap_var, grad_energy, blockiness, noise_ratio, aliasing`
- Config file support: `--config config.yaml` or auto-detect `lucid_config.yaml`
- Robust error handling: corrupted images logged to `errors.log`, continue processing
- Disk space check before starting
- Optional HF datasets: `--input dataset:username/name` for HuggingFace support

**Script `audit.py` (cleaned)**:
- Progress bar with ETA
- Summary report: "Fixed 123 color profiles, found 4 corrupt files"
- Option: `--fix` to auto-correct, `--report-only` to just list issues

**Script `dedupe.py` (cleaned)**:
- Memory-efficient sliding window (already good)
- Clear similarity report: "Removed 12,345 redundant tiles (32% reduction)"
- `--dry-run` flag to predict dedupe impact
- Option: `--delete` vs `--move-to` for safety

**Script `finalize.py` (simplified)**:
- Auto-detect dataset name from input folder
- Sequential numbering 000000.png, 000001.png, ...
- Write `manifest.csv` automatically
- No multi-dataset append complexity (just one dataset at a time)

### A5. Configuration Strategy

**Default thresholds** (in code, overrideable via CLI or config file):
```yaml
filter:
  tile_size: 256
  multi_scale: true  # [1.0, 0.75, 0.5, 0.25]
  quality:
    entropy_min: 5.2
    lap_var_min: 80.0
    lap_var_max: 10000.0
    blockiness_max: 45.0
    aliasing_max: 0.65
    grad_energy_min: 0.70
    noise_ratio_max: 0.65
  complexity:
    threshold: 0.60  # IC9600 minimum
    icnet_model: "models/complexity.pth"
dedupe:
  threshold: 0.96  # cosine similarity
  batch_size: 128
```

## Part C: User's OS Upgrade Question

**Current**: Ubuntu version unspecified
**Consideration**: Garuda Linux (Arch-based) has newer packages but is less stable; Ubuntu LTS is rock-solid for ML work.

**Recommendation**: 
- If you need latest CUDA drivers and gaming focus → Garuda "Dr460nized Gaming" is fine
- If you prioritize stability and known-good Docker/PyTorch ecosystem → stay on Ubuntu or try Ubuntu 24.04 LTS
- Before switching: test your entire training pipeline on a live USB to verify CUDA/driver compatibility

**Upgrade path**: Backup /home, do fresh install, restore datasets from external drive, reinstall environment via `uv sync` or conda env export.
